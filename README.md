## 1 サービス概要 

プログラミング初学者が学習中のつまずきを記録・振り返るためのアプリです。   
わからなかったことから解決までの過程を蓄積し、同じ内容でつまずいたときに見返すことで、小さなつまずきによる学習の停滞や挫折を減らすことを目指します。 

## 2. このアイデアはどこから生まれたのか 
 
### 2-1. きっかけとなった体験・感情 
 
未経験からプログラミングの学習を進めていく中で、「一度学んだことを思い出せない」「さっき理解したはずなのに、応用問題になると活用できない」と感じることがありました。 
 
こうした小さなつまずきが続くと、「今日はもう勉強をやめようかな」「またあんなに時間がかかるなら始めたくない」と、学習への意欲が下がっていきました。 
 
### 2-2. なぜそれが気になったのか 
 
私は、「これはこういうものだから」とそのまま受け入れて学習を進めることが苦手です。なぜそのような動きをするのかを自分なりに解釈し、納得できないと、一度覚えたことでもすぐに忘れてしまったり、自発的に活用できなくなると感じてしまいます。 
 
そのため、理解できなかったことを自分の言葉で整理し、あとから何度でも見返せる仕組みが必要だと考えるようになりました。 
 
## 3. 課題の整理 
 
### 3-1. 表に見えている困りごと 
 
一度学んだ内容を何度も忘れてしまい、理解し直すために時間がかかる。 

その結果、学習をスムーズに進められない。 
 
### 3-2. 本当に解決したい課題は何か 
 
- なぜ学習がスムーズに進まないのか？   
 → 一度学んだ事を思い出せず、同じことを何度も調べてしまう。 
 
- なぜ何度も調べてしまうのか？   
 → わからなかった理由や過程を自分の言葉で整理できておらず、知識が定着しないため。 
 
- なぜそれが困るのか？   
 → 小さな失敗や理解できない経験が積み重なり、「自分には向いていない」と感じて学習意欲が下がり、途中でやめてしまうため。 


本当に解決したい課題：
学習中のつまずきによって自信を失い、学習が継続できなくなってしまうこと

## 4. 想定ユーザーについて 
 
### 4-1. 想定しているユーザー 
 
年齢設定： 
 
- 年齢：25〜35歳 
- 理由：仕事に慣れ始め、転職やキャリアアップを目的に未経験分野の学習を始める人が多いため。 
 
生活・状況設定： 
 
- 生活・状況：フルタイムで働き、帰宅後や休日を使って、未経験からプログラミングを学習している。
- 理由：限られた時間で学習するため、同じ内容を何度も調べ直したり、理解できないまま先へ進んだりすると、学習効率が下がり、途中で離脱しやすくなるため。 
 
環境設定： 
 
- 環境：自宅で一人、オンライン教材や書籍を使って学習している。 
- 理由：理解できなかった内容や自分なりの解釈を記録し、いつでも見返せる仕組みにより、学習の停滞や挫折を減らすことができる。 
 
### 4-2. 自分とユーザーの距離 
 
- 自分自身 
 
理由：私自身が同じ課題を感じており、学習中に理解できないことや、以前学んだ内容を思い出せない事による不安を経験しているため、ユーザーが感じる悩みや行動を具体的に想像できます。 
 
### 4-3. 実際に使われる可能性について 
 
- 最初に使ってくれそうな人：未経験からプログラミング学習を始めた初学者 
- 利用シーン：学習中にわからない単語や手順が出てきたとき、以前つまずいた内容を思い出したいとき 
- 代替手段：技術記事の投稿サイト、検索エンジン、メモ帳 
- それらを置き換えて使う理由：記事を読むだけでなく、自分が理解できなかったことや失敗したことを自分の言葉で蓄積し、あとから見返せるため。 
 
### 4-4. ユーザーがサービスを導入して利用するまでのイメージ 
 
- きっかけ：学習を進める中で、わからない単語や手順が出てきたとき 
- 最初の一歩：ユーザー登録後、理解できなかったことやできなかったことを投稿する 
- 継続する理由：学習中のつまずきや自分なりの解釈が蓄積されるため、同じ内容で困ったときにすぐ見返せる。過去の自分の成長も確認でき、モチベーションにつながる。 
 
## 5. 既存サービスとの差別化 

### 5-1. 似たサービスの調査 

- サービス名：Qiita 
- URL：https://qiita.com/ 
- どんなことができるか：   
 エンジニア向けの技術情報共有サービス。技術記事の投稿、他ユーザーの記事を検索・閲覧もできます。
 
- サービス名：Notion 
- URL：https://www.notion.so/ 
- どんなことができるか：   
 メモやデータベースを作成し、情報を自由に整理・管理できるサービスです。 
 
### 5-2. それでも自分が作りたい理由 
 
既存の技術記事サイトや検索エンジンを使えば、わからないことを調べて解決することはできます。しかし、自分のつまずきから解決までの過程を残すことには向いていないと感じています。 
 
私は、正確で膨大にある情報だけではなく、理解できなかったときの自分の考えや学習の記録が学習において重要だと考えました。 
 
そのため、できなかったこと・わからなかったことから、解決に至るまでの流れを記録できるアプリを作りたいと思いました。 
 
### 5-3. 差別化を体験価値で表現する 
  
- 私のアプリの差別化ポイント：   
 解決済みの知識を保存するだけでなく、自分の疑問から解決に至るまでの思考や試行錯誤を自分の言葉で振り返れる体験を提供すること。 
 
## 6. このサービスで提供したい価値 
 
### 6-1. ユーザーの変化 
 
- 行動の変化：   
 わからなかったことや失敗したことを記録し、同じ内容でつまずいたときに自分の記録を見返せるようになる。 
 
- 気持ちの変化：   
 「また忘れてしまった」「自分には向いていない」と感じる不安を減らし、学習を続けられるようになる。 
 
- 考え方の変化：   
 失敗を「できなかったこと」で終わらせず、次の理解や成長につながる記録として捉えられるようになる。 
 
### 6-2. 価値を一文で表す 
 
このサービスは、小さなつまずきから学習を諦めそうになる人が、自分のつまずきと解決までの過程を振り返り、学習を続けられるようにするアプリです。

## 8. このアプリの懸念点とその対策 
 
### 懸念点①：ただのメモアプリだと受け取られる可能性 
 
- 何が問題になりそうか：   
 アプリの意図が伝わらなければ、ほかのメモアプリと違いがわからず、使う理由を感じてもらえない可能性がある。 
 
- なぜそう思うか：   
 既存のメモアプリやノートでも代用できると考えられるため。 
 
- そのために考えている対策：   
 「わからなかったこと」から「解決方法」を一連の流れとして記録できる投稿形式にする。また、その流れを蓄積できるようにする。
 
### 懸念点②：つまずきを記録する習慣が定着しない可能性 
 
- 何が問題になりそうか：   
 わからなかったことをその都度記録する手間を感じ、継続して利用しない可能性がある。 
 
- なぜそう思うか：   
 学習中は早く問題を解決して先に進みたいため、記録よりも検索や教材の閲覧を優先することが多いと考えられるため。 
 
- そのために考えている対策：   
 投稿項目を必要最低限にし、短時間で記録できるようにする
 
## 9. 今後の展開・発展の方向性 
 
このアプリは、つまずきを投稿して終わりではなく、記録を振り返り、他者の学習にも役立てられるサービスへ発展させたいと考えています。 
 
 - ユーザーが使い続ける理由 
 
自分が過去につまずいた内容や解決までの過程を振り返ることで、同じ問題に再び直面したときに学習を再開しやすくなります。また、他のユーザーがどのような点でつまずいているかを知ることで、自分だけではないと感じられ、新しい気づきも得られます。 
 
- 続けることで得られる価値 
 
記録が蓄積されることで、自分がつまずきやすい分野や学習時の傾向を把握できます。
  
- 他の人と関わる余地 
 
他のユーザーがつまずき投稿に対して解決方法や参考資料を回答できる機能を追加します。投稿者は回答を参考にしながら、自分が最終的にどのように理解したかを記録できます。 
 
### 今考えている発展案 
 
- 機能追加の方向性 :
 
・ 他ユーザーのつまずきへの回答機能 
・ベストアンサー・解決回答の選択機能 
・つまずきの傾向や解決率を可視化する振り返り機能 
 
- UI・体験の改善 : 
 
・　学習中でも短時間で投稿できる入力画面 
・　過去の似たつまずきを提案する機能 
・　未解決の投稿や、後で見返したい投稿をわかりやすく表示する機能 
 
- 機能以外の工夫 :
 
.失敗やつまずきを前向きに記録できる言葉やデザインを取り入れる

### 10-2. 技術選定の比較検討 
 
| 候補 | 採用/不採用 | 理由 | 
| --- | --- | --- | 
|Ruby 3.3.x | 採用 | 学習してきた技術であり、Rails8系の要件を満たしているため。 |
| Ruby on Rails 8.1.x | 採用 | これまで主に学習してきた技術であり、投稿・検索などの機能を効率よく開発できるため。 | 
| ERB / CSS | 採用 | Railsと組み合わせやすく、MVPに必要な画面をシンプルに実装できるため。 | 
| PostgreSQL | 採用 | Railsで広く利用されており、投稿データやユーザー情報を管理しやすいため。 | 
| Devise | 採用 | ユーザー登録・ログイン機能を効率よく実装できるため。 | 
| Render | 採用 | Railsアプリを比較的簡単にデプロイできるため。 | 
| Tailwind CSS | 不採用 | まずはCSSで基本的な画面を実装する。 | 
#### 今回チャレンジしたい点 
 
- ユーザー認証、投稿、検索、絞り込みなど、Webアプリの基本機能を一連で実装すること 
- つまずきから解決までの流れを、ユーザーが記録しやすい画面として設計すること 
- Renderを使ってアプリをデプロイし、実際に利用できる状態まで公開すること 
 
#### 不安な点 
 
- 投稿・解決方法・カテゴリ・タグなど、複数のデータをどのように関連付けるか 
- 検索や絞り込み機能を、使いやすく実装できるか 
- 開発期間内にMVPの機能を完成させられるか 
 
### 10-3. キャッチアップ不足の懸念 
 
1. **スケジュールが遅れる可能性** 
 
学習中の技術であるため、調査や実装に時間がかかる可能性があります。 
 
 
2. **Issueの見積もりが難しい可能性** 
 
理解が十分でない技術は、実装にどれくらい時間がかかるかを事前に判断しにくいです。
